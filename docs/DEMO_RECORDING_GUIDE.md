# CDAS 教师评审 Demo 录制手册

本手册面向当前版本的 CDAS 录屏演示，默认成片时长为 6-8 分钟，受众为教师评审。主线采用稳定优先策略：现场重点演示教师设计并发布作业、学生领取并提交、教师评分、学生查看反馈，不把实时 AI 结果当作成片成败依赖。

## 1. 演示目标

本次 demo 重点证明 4 个价值：

- 降低设计成本：教师可在结构化编辑器中快速形成跨学科作业草稿。
- 强化过程证据：学生按阶段提交内容、附件和检查点，不只交最终结果。
- 提高评价一致性：教师按统一量规进行评分，反馈可追溯。
- 形成教学闭环：从设计、发布、提交到评价与反馈全链路打通。

讲述口径建议固定为：

`CDAS 面向 K12 跨学科作业场景，核心不是替代老师，而是帮助老师更快完成设计、发布、过程跟踪和评价闭环。`

## 2. 录制前准备

### 2.1 启动服务

后端：

```bash
source .venv/bin/activate
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

前端：

```bash
cd frontend
npm run dev:local
```

### 2.2 准备演示数据

推荐先执行 demo 数据准备脚本：

```bash
source .venv/bin/activate
python scripts/prepare_demo_data.py
```

脚本会准备以下数据：

- 一个教师账号
- 一个学生账号
- 一个演示班级和一个可展示的小组
- 三个备份作业
- `备份A`：已发布，可用于从学生领取开始继续录
- `备份B`：已提交，可用于从教师评分开始继续录
- `备份C`：已评分，可用于直接录学生查看反馈

脚本执行完成后会打印：

- 教师/学生账号和密码
- 班级名称、邀请码、小组名称
- 各备份作业的标题、作业 ID、评分页 URL
- 建议现场新建的“主录作业”固定字段

### 2.3 画面规范

- 浏览器宽度保持在 1440px 以上
- 缩放固定为 100%
- 隐藏书签栏和无关标签页
- 关闭系统通知、即时通信弹窗和自动更新提示
- 页面切换前后停顿 0.5-1 秒，给剪辑留点
- 鼠标先悬停后点击，避免扫射式移动

## 3. 主录顺序

按以下顺序录，避免频繁来回找页面：

1. `/auth` 教师登录
2. `/` 教师仪表盘
3. `/create` 设计作业、保存草稿、发布作业
4. `/classes` 展示班级邀请码与小组能力
5. `/auth` 切换学生账号
6. `/student` 学生首页
7. `/assignment/:id` 学生开始作业、保存草稿、提交
8. `/auth` 切回教师
9. `/assignment/:id` 教师查看提交
10. `/grading/:submissionId` 教师评分
11. `/auth` 切回学生
12. `/assignment/:id` 学生查看反馈
13. `/knowledge` 作为可选补镜头

## 4. 分镜脚本

### 镜头 A：教师登录（0:00-0:35）

动作：

- 打开 `/auth`
- 选择 `我是教师`
- 登录后进入首页

口播：

- `CDAS 面向 K12 跨学科作业场景，重点帮助教师完成设计、发布、提交和评价闭环。`
- `这里教师仍然是最终决策者，AI 只做辅助，不会替代教师判断。`

### 镜头 B：教师仪表盘（0:35-1:05）

动作：

- 停留 8-10 秒
- 指向草稿、已发布、班级管理卡片
- 指向最近作业列表

口播：

- `教师登录后直接进入任务总览，看到草稿、已发布作业和班级管理入口。`
- `这里不是单纯展示列表，而是把教师最常用的入口和当前状态先聚合出来。`

### 镜头 C：设计并发布作业（1:05-2:55）

动作：

- 进入 `/create`
- 填写或展示固定字段
- 重点停留在基本信息、学科配置、任务步骤、评价维度
- 点击 `保存草稿`
- 点击 `发布作业`

建议固定字段：

- 作业标题：`校园节水行动`
- 主题：`围绕校园节水提出跨学科改进方案`
- 学段：`初中`
- 年级：`7 年级`
- 主学科：优先使用 `科学`，如当前环境无该学科，则以 `scripts/prepare_demo_data.py` 输出为准
- 融合学科：优先使用 `数学、语文`，如当前环境学科集不同，则以脚本输出为准
- 作业类型：`探究型`
- 提交模式：`分阶段`
- 时长：`2 周`

口播：

- `老师可以先形成结构化草稿，再决定是否发布。`
- `设计器重点聚焦主题、学科、阶段任务和评价维度，减少无效字段干扰。`
- `这里保留了教师主导权，AI 只是辅助，不会替代最终判断。`

现场不深讲：

- prompt 版本号
- RAG 元数据
- 历史草稿的复杂分支

### 镜头 D：班级与小组（2:55-3:40）

动作：

- 进入 `/classes`
- 展示班级名称、邀请码、小组列表、成员分配区

口播：

- `发布作业之后，系统还支持面向真实班级组织与小组协作。`
- `教师不仅是在发一份作业，更是在组织一个真实的课堂任务。`

### 镜头 E：学生首页（3:40-4:00）

动作：

- 切换到学生账号
- 进入 `/student`
- 展示已发布作业卡片

口播：

- `学生只看到与自己年级相关、已经发布的任务，权限边界比较清晰。`

### 镜头 F：学生提交（4:00-5:05）

动作：

- 打开作业详情
- 展示当前阶段任务、学习支架、证据要求
- 点击 `开始作业`
- 填写正文
- 添加一个附件链接
- 保存草稿
- 提交本阶段

建议正文文案：

`我们观察了教学楼与食堂附近的用水情况，发现午间饮水点和卫生间是高频用水区域。我们计划通过问卷、观察记录和数据统计，分析浪费发生的时间段与原因。`

建议附件：

- 文件名：`节水观察记录.pdf`
- 链接：`https://example.com/cdas-demo-water-observation`

口播：

- `这里强调的是过程证据，而不是只收最终答案。`
- `学生可以先保存，再正式提交，比较贴近真实课堂节奏。`
- `每个阶段都能明确看到当前任务和证据要求。`

### 镜头 G：教师评分（5:05-6:20）

动作：

- 切回教师
- 打开作业详情或评分入口
- 展示提交内容、附件、检查点
- 进入评分页
- 调整 1-2 个维度分数
- 填写反馈并提交评分

建议评分：

- 总分：`3`
- 等级：`良好`
- 反馈：
  `证据收集方向明确，已经形成问题意识和基本分析框架。下一步建议补充更具体的数据来源，并把节水建议和统计结果建立更清晰的对应关系。`

口播：

- `教师评分既能看结果，也能回看过程证据。`
- `评价标准统一为四档，反馈能直接给到学生。`
- `AI 辅助评分能力已经接入，但教师仍然是最终确认者。`

说明：

- 若现场网络不稳，不点击 `AI 辅助`
- 若学生提交流程失败，可直接切换到脚本生成的 `备份B`

### 镜头 H：学生查看反馈（6:20-6:50）

动作：

- 切回学生
- 打开同一作业
- 展示分数、等级、教师反馈

口播：

- `学生看到的不只是一个分数，而是下一步如何改进。`
- `这也是 CDAS 想解决的关键问题：把设计、提交、评价真正连成闭环。`

### 镜头 I：可选补镜头（6:50-7:10）

动作：

- 进入 `/knowledge`
- 快速展示系统内置课程标准知识库和文档上传入口

口播：

- `知识库和教案生成能力已经接入，但本次演示重点放在稳定闭环。`
- `当前版本已经具备课堂试点所需的核心流程。`

## 5. 备份切换策略

如果主录中断，按下面方式切换：

| 场景 | 切换目标 |
| --- | --- |
| 教师创建或发布失败 | 使用 `备份A`，从学生领取开始继续录 |
| 学生提交失败 | 使用 `备份B`，从教师查看提交与评分继续录 |
| 教师评分失败 | 使用 `备份C`，直接录学生查看反馈 |

脚本会输出对应的：

- 作业标题
- 作业详情页 ID
- 评分页 URL

## 6. Rehearsal 检查项

正式录制前逐项确认：

1. 教师账号能登录
2. 学生账号能登录
3. 教师首页能正常打开
4. `设计作业` 页面能保存草稿
5. `班级与小组` 页面已有班级、邀请码和可见成员
6. 学生首页能看到目标作业
7. 学生提交流程可完成
8. 教师评分流程可完成
9. 学生能看到评分结果与反馈
10. `/knowledge` 页面可正常打开

## 7. 不建议现场冒险演示的内容

- 首次上传大文件并等待索引完成
- 把实时 AI 生成当作主镜头
- 临时创建大量班级、小组或多学生数据
- 任何需要长时间等待网络响应的流程
- 复杂异常路径和权限对抗演示

## 8. 配合脚本的使用建议

推荐组合方式：

1. 启动前后端
2. 执行 `python scripts/prepare_demo_data.py`
3. 按脚本输出记录账号、邀请码和备份作业 ID
4. 正式录制时现场新建“主录作业”
5. 如任一步失败，切到脚本提供的备份作业继续

这样能同时满足两个目标：

- 主线演示保持真实、顺滑
- 任何单点故障都不会打断成片
